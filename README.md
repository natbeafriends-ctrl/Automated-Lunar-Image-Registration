# Lunar Surface Image Registration Pipeline

Aligns two photos of the same lunar spot taken at different times (different
sun angle, possibly different scale/rotation), using SIFT feature matching
and RANSAC-filtered homography estimation.

## Files
- `lunar_registration.py` — the pipeline (SIFT → FLANN match + ratio test →
  RANSAC homography → warp → overlay)
- `make_test_images.py` — generates a synthetic test pair (crater terrain,
  same physical texture, two different sun angles, known ground-truth
  rotate+scale+translate) so the pipeline can be validated before using real
  ISRO data
- `validate_rmse.py` — computes a reproducible accuracy (RMSE) score by
  comparing the pipeline's estimated transform against the known ground-truth
  crater positions
- `photo1_sun_upper_left.png`, `photo2_sun_moderate_shift.png` — the
  generated synthetic test pair
- `results/` — output panels: all matches → RANSAC inliers → alpha overlay →
  checkerboard overlay (generated by running the pipeline, not committed)

## Run it
```bash
python make_test_images.py
python lunar_registration.py photo1_sun_upper_left.png photo2_sun_moderate_shift.png --out results
python validate_rmse.py
```

Options for `lunar_registration.py`:
- `--out` (default `results`) — output directory
- `--ratio` (default `0.75`) — Lowe's ratio test threshold (lower = stricter matches)
- `--reproj` (default `5.0`) — RANSAC pixel-distance threshold for inlier acceptance

The pipeline currently estimates a full homography (`cv2.findHomography`).
An affine-only mode (rotation + uniform scale + translation, appropriate when
no real perspective distortion is expected) is a planned addition — see
Future Work below.

## Validated result (synthetic pair, moderate sun-angle shift)
- 4,705 good matches after ratio test → 4,670 RANSAC inliers (99.3%)
- Recovered transform vs. known ground truth: rotation 12.0° (true 12°),
  scale 1.150× (true 1.15×)
- **RMSE = 0.09 px**, measured against 33 known crater-center control points
  (reproducible via `validate_rmse.py`)

## Stress test: full sun-angle reversal
We also tested a worst-case scenario — sun angle fully reversed
(upper-left → upper-right lighting) instead of a moderate shift:
- Good matches: 3,628 (down from 4,705, but still strong)
- RANSAC inliers: 3,613 (99.6%)
- Transform still recovered correctly; alignment remained visually clean

**Caveat on this result:** our synthetic terrain's surface grain texture is
added identically regardless of `light_dir` and is only affected by the
geometric warp, not by relighting. Real lunar regolith texture visibility
changes with sun angle (shadow length/contrast), so this benchmark likely
still under-represents how hard real extreme-lighting pairs would be. We're
treating this as a known limitation of the synthetic benchmark, not a claim
about real-world extreme-lighting performance — see Future Work.

## Using with real images
1. Replace the two PNG paths with your real photo pair.
2. Run the pipeline as above; inspect `results/03_overlay_panel.png` for
   visual alignment quality.
3. For an accuracy number on real images (no known ground truth available),
   manually pick 5–10 matching points you can verify by eye in both images
   and pass them to `compute_rmse()` in `lunar_registration.py`.
4. If match count collapses on a real extreme-lighting pair, that's a
   signal to try a learned feature matcher (e.g. LoFTR) instead of SIFT.

## Future Work
- Add an `--transform affine` mode using `cv2.estimateAffinePartial2D`
  (4 DOF: rotation, uniform scale, translation) for cases with few matches,
  where the extra DOF of a full homography can overfit to noise — not yet
  implemented.
- Re-render synthetic surface texture so it responds to `light_dir` (rather
  than being geometrically warped but photometrically fixed), so the
  extreme-lighting stress test is a genuinely harder benchmark.
- Validate against real ISRO/lunar orbiter imagery.
- Evaluate LoFTR as an illumination-robust alternative for extreme-lighting
  pairs where SIFT match counts collapse.
